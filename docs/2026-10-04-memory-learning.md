# EvolvMem 记忆学习与协作体系

## 目标与边界
- 用户可看到 AI 学到什么、依据什么，纠正记忆并检查受影响的协作规则。
- 建立可编辑的协作 Skill 框架；对话产生有来源的记忆，再分析项目及同类项目记忆完善规则。
- 用户已选择：明确且无冲突的规则自动更新；推断、冲突及扩大范围的变化待确认。
- 管理继续在现有知识库工作台内，复用 SQLite、现有提炼模型与客户端，不新增服务或依赖。
- 不训练模型、不增加自主开发执行器，不将愿景举例硬编码为每次必须执行的流程。

## 设计
- 记忆增加独立用途分类：长期习惯、项目约定、任务要求、环境事实、决策、经验、参考；保留原有项目、内容类型和状态。
- 新提炼附用户原话、来源会话/归档、适用时机、理由和明确/推断标识；无法核对的证据留待确认。
- 仅有明确用户原话、可信归属、持续适用且无冲突的规则自动启用；从多份记忆归纳的规则作为候选。
- 项目可指定项目类型，同类型分析使用该组实际记忆，候选规则必须引用输入资料，不能越过范围。
- 协作 Skill 由可编辑框架和已生效规则组成，规则分全局、项目、项目类型。保存版本，支持比较和恢复。
- 记忆纠正、归档或来源变化使旧衍生规则停止被调用，页面展示原因；人工编辑和否决不被自动分析覆盖。
- CLI/Web 共用核心；会话接入提供当前适用规则，安装轻量协作 Skill 引导主动获取最新内容。
- 既有记忆保留原状，按类型给出分类建议；用户可选择范围分析，旧内容不会自动被当成长期已确认规则。

## 实施与验收
1. 添加学习元数据、来源校验、明确规则自动更新与冲突待确认；测试伪造引用、临时要求、重复提炼和作用域。
2. 添加项目类型、基于记忆的分析、框架编辑、规则审阅及版本恢复；测试修订后召回和历史版本恢复。
3. 接通真实提炼与会话调用路径；验证源记忆纠正后不再提供旧规则。
4. 在知识库内添加学习成果、协作 Skill、来源与纠正操作；浏览器验证完整操作和手机布局。
5. 更新架构图与使用说明，完成相关回归、实际服务验收、总控台登记及 GitHub/Gitea 同步。

## 方案选择
采用现有知识条目加学习元数据与规则版本，保留项目边界和现有经验验证。
只改提示词无法展示来源、纠正传播与版本变化；独立新平台会重复存储和接入，本轮均不采用。

## P1：协作过程提炼与规则试运行

- 原知识库的“入库规则”页增加提炼说明、明确规则自动生效开关和样例对比；“管理 Skill”仍与其共用一份文件。预览比较已保存规则与未保存草稿，不写入资料。
- 每条原子知识可以保留目标、AI 理解、用户纠正、明确决定及验证陈述；原话必须匹配消息与角色。助手自称完成不算成功证据，缺少的阶段不补造。
- 相关旧知识带资料 ID 和版本；处理分为新增、补充、替代、跳过。同内容不同条件保留分支；自动替代须有用户同时指明旧内容与新要求的原话，并核对范围和当前版本。疑难变化进入候选，保留旧知识。
- Kimi 与 Codex 复用提炼提示和写入判定；Kimi 归一化候选时保留学习元数据。提炼期间规则版本变化则回滚并重试，避免用旧提炼结果套新门槛。
- 常态旧知识对照通过 `related_memory_projects` 选择项目，默认空列表。用户选择后，最多附带 20 条相关有效资料、总计 8,000 字；预览单独勾选是否附带旧知识，不因预览自动开启后续分析。
- 本阶段不执行存量批量回填；后台整合、缺口池和效果度量沿用后续 P2–P4 计划。

使用：打开 `/#knowledge/projects` 选择项目，先读摘要和完整项目正文，再展开历次整理后的对话或来源片段。修改来源、更改归属和归档会反映到总记忆；不同项目始终隔离。

## 项目总记忆与清洗流程（2026-10-05）

- 流程为：同步对话 → 清洗提炼 → 入库成文 → 学习规则。第 3 步的“待确认”只处理资料归属或内容；第 4 步的“规则待确认”决定 AI 今后如何协作，两者在页面标明。
- `conversation.py` 统一移除工具记录、推理通道与已知注入包装；真实交流保留顺序。新归档保存整理后的对话视图，旧归档读取时清洗；底层原始归档继续用于证据核对，不在对话阅读区展示。
- Codex/Kimi 提炼及编辑器试运行先清洗后调用模型，候选再经既有质量、来源、去重与归属检查入库。不能把“已同步”当成“已入库”。
- `project_memory.py` 只汇集当前有效历史会话摘要与任务记录，形成一份总记忆与确定性摘录。经验、习惯和约定以简洁问答分别保存和检索。来源归档或移走后，旧快照不能恢复已纠正内容。
- Windows 按显式的 `目录 → 项目标识` 映射同步，目录名、中文显示名称和规范项目标识分别管理；多目录可绑定同一项目，子目录沿用最长匹配映射，未绑定目录不凭名称猜归属。
- `/#knowledge/rules` 在同一列按“1 调整规则 → 2 试运行效果 → 3 保存更改”切换，保留未保存输入。内容说明按需展开，对话提炼比较草稿，资料判断使用已保存规则。
- 本轮不做全库模型回填、不改变真实客户端目录归属；现存工具证据和来源记录保留。新增快照表可重建，不取代原资料。

- 正式项目卡片只列有效登记项目；未登记名称、别名遗留资料和归档项目集中在同页折叠区，避免把旧名称重复显示为项目。同名登记项目显示标识并保留核对提示，不按名称擅自合并。总记忆中相同正文和适用条件只出现一次，所有来源编号仍保留。

## 双类记忆实施（用户已确认）

目标：清洗对话作为历史记录入 SQLite，简洁问答作为可复用知识；项目内集中查看，按意图分别检索。
- 历史正文表与归档接入：新对话自动清洗保存，旧归档按已归属项目的当前会话版本本地幂等迁移；摘要关联正文，失效来源不伪造。
- 问答结构与提炼接入：问、答、分类、条件及来源；明确自动入库，推断/冲突待确认，纠正后旧衍生内容失效。
- 两类检索与 Skill：历史返回摘要及正文入口，经验返回适用问答；显式 kind 优先，混合问题可组合；保持预算与项目边界。
- 同页管理：项目总览、历史记录、经验问答集中切换；编辑、分类、待确认和迁移有明确标记。
- 验证与发布：关键行为测试、浏览器操作、图文、旧数据迁移、服务登记和两个源码仓库同步。
复用现有 SQLite、模型提炼、归属和版本机制；不新增服务，不执行未经选择的存量模型分析，不凭同名强行合并项目。


## 完整用例验收（2026-10-05）
- 后端：全量正式测试 `python -m pytest tests -q`；涵盖清洗、迁移、来源丢失、项目隔离、简洁问答、来源失效、修订冲突、历史/经验检索预算、规则与版本。
- 浏览器：`tests/browser/knowledge_fixture.py` 只创建临时合成数据库，模型响应为固定样例；`knowledge_dual.e2e.cjs` 验证两类记忆闭环，`knowledge_workbench.e2e.cjs` 验证导航、资料状态、归属、规则、Skill 版本和四种屏宽。
- 浏览器依赖复用本机 Playwright：指定 `PLAYWRIGHT_MODULE` 与 `CHROMIUM_EXECUTABLE`；默认夹具端口 39478，可用 `EVOLVMEM_TEST_PORT` / `EVOLVMEM_TEST_URL` 覆盖。不得指向真实业务服务运行写入用例。
- 架构：`/workflow#memory-ingestion` 是入库活动图，`/workflow#memory-recall` 是按意图检索流程图；16 个专题都经过 9 项生成验证，视觉核验另行记录。
- 边界：不以合成模型测试声称已验证真实模型提炼质量。Windows 桌面宿主、DPAPI 和任务计划测试需要 Windows；旧 parent_sha256 诊断脚本不代表当前 source_order/current_sha256 协议。

验证结果：正式测试 2521 项通过、60 项因环境条件跳过；新增全局归属确认用例后，相关 49 项回归通过；两套浏览器脚本通过，8 个界面 × 4 种屏宽检查无溢出，无页面脚本异常。Windows 实机只读核实 `D:\Evolvmem → evolvmem` 显式映射；不宣称已完成桌面宿主注入全链路验收。


## 提炼依据与完整问答校验（2026-10-07）

- 原子知识必须带完整问答，答案与正文一致；仅有助手原话、缺少问答或标为推断的候选不能自动成为用户决定。
- 用户要求与助手补充分条保留。引用存在不等于支持整条答案；提炼提示要求每个实质断言有对应用户依据，一次性要求保留任务范围。清洗稿只是派生资料，不等于用户确认。
- 保留原有经验案例结构、长期约定范围及旧知识补充/替代字段；未验证经验继续隔离，历史记录不自动重写。
- 验证：相关回归 156 通过；全量 2628 通过、60 跳过、10 失败，失败用例与改动前一致（分发启动及旧页面跳转），本轮不宣称全量通过。
- 最终提示连续两次真实只读提炼均返回完整问答，明确要求与助手补充正确分开；样本与原始响应仅保存在本地，未写入真实业务记录。此结果不代表所有资料都能自动得到正确结论。
- `tests/browser/product_modules.e2e.cjs` 的 11 项检查通过；已查看入库及自动整理活动图截图，确认节点文字可读。当前图源为 `web_static/principles.js`，入口 `/#principles`。
