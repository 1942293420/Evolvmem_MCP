# EvolvMem 记忆学习与协作体系

## 目标与边界
- 用户可看到 AI 学到什么、依据什么，纠正记忆并检查受影响的协作规则。
- 建立可编辑的协作 Skill 框架；对话产生有来源的记忆，再分析项目及同类项目记忆完善规则。
- 用户已选择：明确且无冲突的规则自动更新；推断、冲突及扩大范围的变化待确认。
- 管理继续在现有知识库工作台内，复用 SQLite、现有提炼模型与客户端，不新增服务或依赖。
- 不训练模型、不增加自主开发执行器，不将愿景举例硬编码为每次必须执行的流程。

## 设计
- 记忆增加独立用途分类：长期习惯、项目约定、任务要求、环境事实、决策、经验、参考；保留原有项目、内容类型和状态。
- 新提炼附用户原话、来源会话/归档、适用时机、理由和明确/推断标识；无法核对的证据留待确认。
- 仅有明确用户原话、可信归属、持续适用且无冲突的规则自动启用；从多份记忆归纳的规则作为候选。
- 项目可指定项目类型，同类型分析使用该组实际记忆，候选规则必须引用输入资料，不能越过范围。
- 协作 Skill 由可编辑框架和已生效规则组成，规则分全局、项目、项目类型。保存版本，支持比较和恢复。
- 记忆纠正、归档或来源变化使旧衍生规则停止被调用，页面展示原因；人工编辑和否决不被自动分析覆盖。
- CLI/Web 共用核心；会话接入提供当前适用规则，安装轻量协作 Skill 引导主动获取最新内容。
- 既有记忆保留原状，按类型给出分类建议；用户可选择范围分析，旧内容不会自动被当成长期已确认规则。

## 实施与验收
1. 添加学习元数据、来源校验、明确规则自动更新与冲突待确认；测试伪造引用、临时要求、重复提炼和作用域。
2. 添加项目类型、基于记忆的分析、框架编辑、规则审阅及版本恢复；测试修订后召回和历史版本恢复。
3. 接通真实提炼与会话调用路径；验证源记忆纠正后不再提供旧规则。
4. 在知识库内添加学习成果、协作 Skill、来源与纠正操作；浏览器验证完整操作和手机布局。
5. 更新架构图与使用说明，完成相关回归、实际服务验收、总控台登记及 GitHub/Gitea 同步。

## 方案选择
采用现有知识条目加学习元数据与规则版本，保留项目边界和现有经验验证。
只改提示词无法展示来源、纠正传播与版本变化；独立新平台会重复存储和接入，本轮均不采用。

## P1：协作过程提炼与规则试运行

- 原知识库的“入库规则”页增加提炼说明、明确规则自动生效开关和样例对比；“管理 Skill”仍与其共用一份文件。预览比较已保存规则与未保存草稿，不写入资料。
- 每条原子知识可以保留目标、AI 理解、用户纠正、明确决定及验证陈述；原话必须匹配消息与角色。助手自称完成不算成功证据，缺少的阶段不补造。
- 相关旧知识带资料 ID 和版本；处理分为新增、补充、替代、跳过。同内容不同条件保留分支；自动替代须有用户同时指明旧内容与新要求的原话，并核对范围和当前版本。疑难变化进入候选，保留旧知识。
- Kimi 与 Codex 复用提炼提示和写入判定；Kimi 归一化候选时保留学习元数据。提炼期间规则版本变化则回滚并重试，避免用旧提炼结果套新门槛。
- 常态旧知识对照通过 `related_memory_projects` 选择项目，默认空列表。用户选择后，最多附带 20 条相关有效资料、总计 8,000 字；预览单独勾选是否附带旧知识，不因预览自动开启后续分析。
- 本阶段不执行存量批量回填；后台整合、缺口池和效果度量沿用后续 P2–P4 计划。

使用：打开 `/#knowledge/rules`，左侧修改规则，右侧试运行，最后使用顶部唯一的“保存更改”。内容筛选、旧知识对照和 AI 说明按需展开。试运行可切换“对话提炼 / 资料判断”，切换与保存保留样例输入；对话比较已保存规则与当前草稿，资料判断只使用已保存规则。结果在下方并排对照，手机自动纵向排列。资料详情及学习规则来源可以展开查看协作过程。

本次布局整理仅调整现有工作台，提炼、入库及 Skill 共用来源的流程未变；已核对工作原理图“记忆学习”专题仍适用。
