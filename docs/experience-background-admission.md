# LAN 经验召回的后台健康准入

这次改动只把 `experience_recall` 的全库健康扫描移出前台请求。能力召回已有独立实现；其他 Context 入口、普通完整诊断以及写操作仍使用原有检查。本次没有宣称全部召回统一优化、无锁，或已经完成十几人并发验收。

## 请求怎样执行

1. 保留认证、身份覆盖限制、参数和工具契约校验。后台健康服务启用时，经验入口使用固定工具目录核对参数，避免在目录查询与 handler 前置检查中触发完整健康评估。
2. 按本次 `space` 选择真正读取的命名空间。`personal` 检查当前认证用户的库；`public` 检查公共库；`both` 分别检查两者，不能用个人库健康结果替代公共库。
3. 每个命名空间都调用实际 `BackgroundHealth.status()`，要求 `hard_gate == allowed` 且 `diagnostic.last_checked_ready is True`。后台尚无基线、配置/数据库身份改变、完整性失败或过期、检查失败、最后检查未就绪，都拒绝继续；不会在请求中重扫以尝试修复。
4. 在原共享调度锁和远程身份作用域内，执行原经验检索与筛选。结果返回前再次检查所有实际读取命名空间的后台状态；若此时不再允许，丢弃本次已计算结果并返回固定错误。

准入只保存在当前请求的 `ContextVar`，绑定具体 server、service 和命名空间。它不会改变驻留服务的 `_ready`，不会构造一个假的完整 `ContextServiceStatus`，不会给完整健康缓存或结果缓存写入新结论。跨线程、新请求、服务替换或不同命名空间不能借用它。后台服务尚未启用时，以及独立 MCP 路径，仍执行原检查。

## 两条召回链的边界

| 项目 | 能力召回 `capability_search` | 经验召回 `experience_recall` |
| --- | --- | --- |
| 业务内容 | 当前能力记忆及支持来源 | 已保存的方法案例与适用条件；公共部分是未验证的人工摘要 |
| 准入 | 已有后台硬基线检查 | 本次新增：所读各库的真实硬基线及最后检查就绪状态，执行前后各检查一次 |
| 内容判断 | 当前候选证明及返回前选中结果的独立最终核验，含来源、归属和价值依据 | 复用原资格、范围、条件、验证与证据解释链；未替换为能力召回的最终来源核验 |
| 连接与锁 | 已有独立读取连接及专用并发限额，仍有模型/索引协调 | 保留原驻留连接、共享调度锁与身份作用域 |

经验链原有的候选资格、状态与有效期筛选、项目/可迁移范围、条件匹配、严格向量降级、验证等级、成功证据条件、矛盾或不适用证据处理及结果格式均未在本补丁中改写。公共摘要仍明确为未验证的共享资料，不能当成个人经验的成功证据。这不是对原经验实现新增“完整实时来源证明”的承诺，也没有声称提升了结果相关性。

后台 `freshness=stale` 只说明内容变化尚待下一轮完整诊断，并不自动取消有效硬基线。经验入口仍要求最后完整检查就绪，并执行其原业务筛选。后台诊断不是当前每一条内容都正常或每个方法都成功的证明。

## 实现与验证

变更限定为 `request_health.py`、`lan_tools.py`、`mcp_server.py`、`context_service.py` 四个运行时文件。`experience_service.py`、`context_retriever.py`、`lan_sharing.py` 与后台扫描实现未改。`memory_search`、`context_search`、`context_session_start`、`context_project_recall`、精确读取等其他入口需要分别核对各自回退、权限和业务边界，不能批量套用本次准入。

修复前的真实运行记录显示，旧经验请求约 49.97 秒，其中完整健康评估约 46.97 秒、检索约 2.65 秒。该记录来自本次事件，不能把单次样本当成稳定延迟基准。隔离原生反例关闭已有的跨请求健康缓存后，确认一次成功经验请求会调用完整前台评估 3 次；生产缓存开启时不代表每次都扫描 3 次。

候选原生回归由集成任务运行：新增 24 项通过；既有 157 项通过、1 项跳过。新增覆盖真实命名空间双端准入、无前台健康评估、未就绪/硬边界改变时拒绝、请求作用域清理，以及原业务条件和证据筛选。回归使用合成 SQLite/LAN 数据；这些结果不代替部署后的真实输出和延迟核验。模型相关可选测试是否跳过，应以该次 pytest 跳过明细为准；本次不为验证此补丁额外启动模型。
