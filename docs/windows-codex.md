# Windows 原生 Codex：EvolvMem 完整功能对齐计划

状态：用户已批准并实施；已通过授权 SSH 完成 Windows 原生核心注入、PowerShell 5.1 加密、计划任务补传及服务端提取验证。用户已确认桌面会话读到项目摘要与任务断点，并以真实仓库完成跨端任务绑定；完整桌面生命周期仍待验收。

## 目标、验收与边界

- 一次安装、一个 EvolvMem MCP 配置入口，使 Windows 原生 Codex 与 Linux 共用同一用户的完整记忆能力。
- 验收覆盖身份、上下文注入、会话归档与总结、项目、任务续接、经验反馈、看板和维护；以同一用户在 Linux 的现有能力为对照。
- 存储沿用原文加密文件与 SQLite 索引、记忆、摘要、任务断点；复用现有提炼器与向量服务。
- 默认覆盖安装后新建和继续使用的本地会话；旧历史批量回填不在本轮范围。
- 仅归档 Codex 已持久化的转写；未落盘、已被删除且未采集的数据不能承诺恢复。
- 可信内网、低并发、现有服务进程；不增加登录系统、数据库服务、Windows 向量模型或 SQLite 文件同步。
- 安装与验收命令见 README 的 Windows 专节；完整功能验收需通过原生桌面版实测，Linux 测试不能替代。

## 一、交付结构

Windows 接入包 → 一个远程 EvolvMem MCP → 现有 Linux 记忆核心。

- 接入包包含用户级安装器、PowerShell 接入脚本、无窗口启动器、全局 AGENTS 规则、Codex hooks 和本地待上传队列。
- 同一个远程 MCP 入口供 Codex 调工具及本地脚本调用；脚本负责会话事件、转写和本机 Git 观察。
- Windows 任务计划每分钟及登录后运行 evolvmem-sync.exe，隐藏启动同一采集脚本，关闭 Codex 后仍可补传；使用系统自带 .NET，不增加 Windows 服务。
- Linux 继续负责身份路由、SQLite、加密归档、提炼、项目、续接、经验与维护。
- 安装器合并现有配置并备份；升级不重复注册，卸载只移除自身配置和任务。用户 NO_PROXY 追加 MCP 主机并保留原值，卸载保留共享环境变量。
- 单填 MCP URL 不具备宿主事件与本地文件采集能力，无法独立完成全套自动化。

## 二、能力与实现方式

| 能力 | 设计 | 验收结果 |
| --- | --- | --- |
| 身份与跨端共用 | 沿用个人凭据，服务端返回 authenticated_user；客户端核对 expected_user | 两端读写同一用户库；凭据不符停止记忆读写并提示 |
| 自动注入 | 启动、恢复、清空、压缩后由命令 hook 拉取并交付上下文；提示词前检查缺失 | 新会话无需手动要求回忆即可取得既有摘要 |
| 会话归档 | 采集已落盘转写，按会话与版本上传并加密，SQLite 仅保存索引 | 可查归档版本、覆盖范围与处理状态 |
| 总结与记忆 | 复用现有提炼、候选筛选、会话摘要与项目滚动摘要 | Windows 新内容可在新会话和 Linux 查询 |
| 项目管理 | 稳定项目标识、中文别名、显式工作区映射 | 不同系统路径归同一项目，同名目录不误合并 |
| 任务续接 | 复用 begin、checkpoint、resume、find、bind 与版本比较 | 跨端恢复目标、决策、进度和下一步；代码差异明确提示 |
| 经验生命周期 | 召回、候选、确认、实际使用和结果反馈共用现有逻辑 | 成功、失败、不适用等反馈可追溯到真实事件 |
| 记忆管理与维护 | 对齐查询、增改删、确认、整理、项目归档、清理与健康状态 | 同一用户的 Linux 功能均有对应入口和测试 |
| 项目看板 | 复用现有同步与状态查询，保持现有配置和调用授权 | 能查询状态，并在已授权调用下同步真实断点 |
| 故障与恢复 | 待上传数据本地持久化，稳定请求标识，分阶段回执 | 断网不假报已保存，恢复后补传且不重复覆盖新内容 |

身份依据是 EvolvMem 凭据所映射的用户，不是 Windows 用户名或 Codex 登录账号；device_id 只区分设备。
跨端共用同一服务端数据。提交后另一端下次读取可见；已打开的会话在下一次提示词或恢复时检查版本。
记忆共用不包含源代码文件同步；Git 分支、提交与工作区变化均从当前机器实际读取。

## 三、上下文注入流程

1. 安装时核对版本、凭据和目录映射；使用同一用户的 Codex CLI `/hooks` 审阅并信任六项 hooks。桌面没有弹窗不代表已信任，自检也不检查信任。
2. SessionStart 覆盖 startup、resume、clear、compact；命令脚本独立访问 MCP，避开客户端连接尚未准备好的时序。
3. 加载通用记忆、项目滚动摘要、相关会话摘要与已绑定任务断点，默认总预算 8000 字符。
4. PowerShell 从 HTTP 原始响应字节按 UTF-8 解码；通过 hookSpecificOutput.additionalContext 交付给 Codex；配置输出阈值，避免有界摘要又被宿主缩成预览。
5. UserPromptSubmit 检查本次启动回执，补取失败或遗漏的加载，并按当前问题补充相关经验、处理服务端版本变化。
6. 同次启动去重；恢复和压缩视为新的加载机会。远程初始化说明避免模型重复执行已由 hook 完成的启动加载。
7. 回执包含身份、项目、摘要与断点版本、获取状态；通过宿主事件或转写核验实际交付，不能把仅成功联网写成已注入。
8. 空库允许有效空结果。服务不可用时提示后继续，不擅自启用严格阻断，也不把旧回执当本次成功。

历史摘要作为参考内容封装，不能覆盖当前用户指令；未绑定目录仅加载通用记忆并标记待归属。

## 四、采集、归档与提炼流程

- 登记前核对转写首条 session_meta 的会话 ID，拒绝父会话误用子会话文件。使用 session_id、transcript_path 和 cwd 登记会话；保留事件标识及工具、用户消息，不以助手自述替代证据。
- Stop、PreCompact 和短时结束事件触发增量采集；后台独立扫描 Codex sessions 与 archived_sessions，按 session_meta 的 ID/cwd 发现新建及恢复会话，弥补未登记和未触发结束事件。
- 安装器保存 codex_root 和 capture_since_utc，升级保留起点；长期未使用的旧历史不自动导入，已有登记继续采集。
- SessionEnd 与 Interrupt 最长只有 3 秒，仅读取未采集尾部并落本地队列，不等待网络或模型；超时覆盖不足必须标记。
- 子代理有独立转写时保留与主会话的关联并去重；主会话中已有的工具结果保留来源。
- 待上传正文用 Windows 当前用户的 DPAPI 加密；PowerShell 5.1 先加载 System.Security。服务端暂存和正式文件沿用现有归档加密。
- 当前缓存锚点先确认，再补传同会话历史；每版本每轮最多 16 块，保存偏移后下轮继续；未变文件避免重复解密，DPAPI 保留 byte[]，降低大日志内存开销。
- 分块最多 256 KiB 原始字节，校验内容摘要、总长度和偏移；只提交完整记录，残缺末行等待后续采集。
- JSONL 只按 LF 分记录，字符串内的 U+0085、U+2028、U+2029 保持原样；经验引用保留原始记录行号与行尾。
- 以认证用户、设备、会话和内容摘要保存不可变版本。
- 每次真实捕获持久化 source_order 和本地 current_sha256；重试次序不变。升级先确认当前缓存锚点，再补传旧版本；缺少可靠缓存时保留队列并报告迁移失败。
- 服务端以显式 head 选择当前快照，不按文件体积或到达时间猜测。合法改写及变短可推进；旧版本完整归档但不覆盖当前、不排队提炼。回退到已归档内容时，以严格更高捕获次序重新选择原不可变归档。
- 当前锚点须收到 archived、自己的摘要和完整长度、archive_id、current=true 及同一 source_order 才确认；历史已归档不等于当前已确认。旧客户端保留追加/分叉校验。
- 每条失败保留稳定 last_error；pending_failed_versions / pending_error_codes 汇总原因。未知服务端文本不写入状态，不丢弃待传。
- 归档完成后复用现有提炼器；短时连续变化合并提炼最新版本，同一版本的重复触发不重复提交记忆。
- 输出会话总结并更新项目滚动摘要；未验证经验仍为候选，后台总结不得直接宣布任务完成。
- 未绑定或混合项目会话保持待归属，不能猜入某个项目；明确后再生成对应项目记录。
- 分别显示任务是否启用、最近 worker/launcher 回执、待上传、已归档、待提炼、已提炼和失败；禁用任务使自检不健康。
- 全局 AGENTS 合并托管段落，指导模型保存重要决定与断点；逐条原文覆盖由后台采集负责，不能靠提示词保证。
- 沿用现有归档期限及证据保留规则；仅在服务端确认完整归档后清理对应本地待传版本。

- 驻留连接出现 `quick_check_failed` 而新连接正常时，无进行中事务的检查改用独立只读连接；事务内仍检查当前连接，真实 FTS 损坏继续失败。合成数据复现了 SQLite 3.53.1 的驻留 FTS 校验误报，但未完全确定线上旧刷新方案漏掉的触发条件，需继续观察真实写入。
