# EvolvMem 知识库管理改版设计

## 目标与验收

将现有记忆控制台改为项目知识库工作台，使用户能找到每个项目的资料、编辑内容、更改归属、处理入库，并编辑 AI 使用的管理 skill 和入库规则。

验收以实际操作结果为准：

1. 主界面的知识库区域按项目展示资料数量和待处理数量，点击项目可以查看全部资料和来源。
2. 不遗漏 Context 中的候选经验、项目摘要、任务断点，以及没有 legacy 映射的记录。
3. 用户可新增和编辑资料；入库后能被对应项目查询，归档后不再用于当前知识召回。
4. 单条或批量修改归属后，新旧项目列表和召回同步更新；人工确认不再被当成未解决。
5. 待入库、待归属、冲突和无决议旧记录有明确入口、原因和操作。
6. 修改入库规则后，后续 AI 提炼和整理读取新规则；页面显示当前生效版本。
7. 管理 skill 可在页面编辑保存，AI 能读取同一份内容和当前规则，避免页面与执行脱节。
8. 浏览器实际验证项目浏览、新建、编辑、改归属、入库、规则保存及 skill 保存；同步流程图、总控台和源码仓库。

## 方案比较

- 推荐：在现有主界面中整合知识库功能和统一 Context 管理接口，复用数据库、提炼器和 MCP。保留现有经验/任务能力，实施成本最小。
- 只扩展旧记忆表：改动较少，但仍遗漏没有 legacy 映射的知识，不满足资料完整管理。
- 新建独立知识库服务：需要重复存储与同步，当前没有必要。

## 页面（最初设计，当前入口与职责见文末 2026-10-05 修订）

沿用 Signal 主界面的浅灰背景和蓝色主色，共用顶部总览、知识库、经验案例、项目进展导航。知识库是主工作台内的功能区；资料、待确认、规则与 Skill 使用页内标签切换，资料详情使用原位对话框，不另设管理站点。

| 知识库内的功能 | 用户能看到什么 | 用户能做什么 |
| --- | --- | --- |
| 项目知识库 | 项目名称、资料数量、待处理数量；全局知识和未归属入口 | 搜索/切换项目，管理项目名称与别名，新增资料 |
| 资料管理 | 文档/参考资料、事实、决策、经验、会话摘要、任务断点；全文、标签、来源、状态 | 编辑、单条/批量改归属、归档、恢复、删除 |
| 入库与整理 | 待入库候选、待归属、归属冲突、旧记录缺少决议，明确显示原因 | 预览建议、采用归属、确认入库、拒绝或暂存 |
| 入库规则 | 自动/审核入库模式、质量门槛、项目识别与冲突处理、保留/忽略规则 | 编辑、保存、用样例预览判定，查看生效版本 |
| 管理 skill | AI 管理知识库的当前 SKILL.md、可用操作、对规则的引用 | 编辑正文、保存、恢复默认、查看/下载；AI 读取当前版本 |

默认入口为统一总览；“知识库”打开项目资料。首页提供项目资料、待确认和规则快捷入口，原项目索引与搜索直接进入知识库筛选结果。旧管理链接兼容跳转；浏览器返回有效，规则和 Skill 未保存时离开会提示。

## 资料和归属

- 统一使用 Context item ID；legacy ID 仅作为兼容信息，不影响新页面能否编辑。
- 详情同时展示正文、来源摘要、来源时间、知识类型和项目归属，不要求用户理解 L0/L1/L2。
- 支持手工新增和粘贴文本/Markdown，项目与资料类型明确选择；保存后可进入待入库或正式入库。
- 内容修改通过核心服务更新分层内容、兼容投影与检索状态；保留来源关系。
- 归属和入库是两个独立状态：资料可以已经入库但归属待确认，也可以项目明确但尚待入库。
- 已人工确认归属应优先于旧自动 unresolved/conflict 状态，修复当前 341 条确认后仍被扣留的问题。
- 同步提炼 key 格式；通用主目录不再直接作为业务项目。明确正文/来源线索进入项目识别流程。
- 旧记录不会仅因现有 project 字段就自动认定可信；在整理队列显示来源、建议及不确定原因。
- 涉及精确任务的改归属按完整任务处理：说明关联记录，在同一事务更新任务及其断点，避免只改列表字段。

## 入库规则与 AI skill

- 默认设计：项目明确、来源充分且符合规则的普通知识自动入库；归属冲突或证据不足的记录进入待确认。用户已明确确认此入库模式。
- 已有经验验证要求继续适用：普通资料入库不等于经验方法已被验证成功。
- 全局规则加可选项目覆盖；界面提供常用规则表单和补充文字说明。
- 规则持久化为受控本地配置，保存后提炼器和整理器按请求读取；自由文字提供给 AI，结构化项用于确定性判断。
- 规则预览说明匹配项目、入库/待确认/忽略及原因；修改默认作用于后续处理，历史整理有独立入口。
- 管理 skill 只有一份受控内容；安装到本机 Codex 可发现位置，页面编辑与 AI 读取引用同一来源。
- skill 描述具体管理行为：查看项目资料、核对来源、整理归属、新增/编辑/入库、读取当前规则；避免要求 AI 在普通聊天中擅自修改资料。
- 新增必要 MCP 管理接口或等效本地入口，使 skill 能实际读取规则和执行已授权的管理操作。

## 实现与验证顺序

1. 修复已确认归属失效，建立统一资料列表/详情及项目统计；测试实际数据状态组合。
2. 建立新增、编辑、改归属和入库核心操作；测试投影、检索和精确任务一致性。
3. 实现项目知识库、资料详情和入库整理队列，浏览器完成一个项目的操作闭环。
4. 实现规则存储、编辑和预览，接入实际提炼/整理路径；验证保存后规则真正生效。
5. 创建管理 skill、编辑页和 AI 读取入口，验证文件格式与操作行为。
6. 同步对应架构图与说明，完成回归和实际入口验证，部署到现有服务，登记总控台并同步 Gitea/GitHub。

## 边界

复用现有单机服务、SQLite、认证和 MCP，不新增登录、权限体系、新数据库或外部服务。
首轮资料输入采用文本/Markdown；PDF/OCR、Office 复杂解析和外部知识源自动爬取不包含在本轮。
不添加独立审计或高并发工程；保留现有事务、版本校验、重复处理护栏，确保管理操作不会留下半完成数据。
仅保留本设计说明，不另外生成 spec/plan/handoff 文档。已实现知识管理核心，并整合至主工作台知识库区域。浏览器闭环通过，交付前完成回归与部署校验。

## 模块职责与处理 Skill（2026-10-05）

| 业务模块 | 负责的内容 | 主界面入口 |
| --- | --- | --- |
| 项目历史 | 新增项目、名称/别名、项目摘要、总记忆、会话摘要与清洗正文 | `#knowledge/projects` |
| 经验知识 | 分类问答、适用条件、需求表达、原话依据；方法案例与独立验证 | `#knowledge/qa`，案例入口 `#experiences` |
| 任务断点 | 目标、已完成步骤、下一步、阻塞、续接提示；不再列项目摘要 | `#progress` |
| 资料整理 | 归属待确认、内容待确认、改归属、编辑、入库、归档 | `#knowledge/intake` |
| Skill 规则 | 项目归属、数据清洗、摘要问答提炼、入库判断、协作学习 | `#knowledge/skill` |

- 经验问答编辑与案例列表均可原位新增项目；创建后立即选中，不丢失问答草稿。沿用唯一项目登记，不新建另一套项目列表。
- 工作原理为主界面功能区 `#principles`，共用导航、样式、返回与前进。模块职责图、业务流程图和 UML 活动图分别回答“谁管什么”“怎么流转”“系统与用户如何协作”。旧 `/workflow`、`/workflow-diagram`、`/architecture` 跳转到此处。
- 图源 `web_static/principles.js` 直接生成 SVG，不依赖 Archify；活动图含开始/结束、动作、条件判断、泳道、分支和汇合。图中文字可放大，小屏在图内滚动。
- 产品顺序：同步对话 → 核对项目归属 → 清洗与提炼 → 历史/知识分别保存 → 按意图调用与学习。不明确的归属和内容均显示待确认原因。接入时基础去噪仍用于移除技术记录，不能据此认定业务项目。
- 五个 Skill 是现有规则的分环节编辑视图。归属/清洗/提炼/入库共用 `knowledge-management/SKILL.md`；协作学习沿用框架和版本表，不产生互相覆盖的副本。
- `GET skills` / `GET skills/{ownership|cleaning|extraction|ingestion|collaboration}` 读取规则。`POST skills/ID` 带 `expected_revision`、`instructions`、本环节 `settings` 保存，保留其他自定义规则。
- 项目归属开放名称别名匹配开关、歧义词与 AI 说明。本地归属预览使用草稿条件；正式整理与提炼读取相同配置，已有人工决定优先。
- 清洗开放完全匹配的提示行过滤、相邻同角色重复消息合并、AI 需求整理说明。历史入库、读取旧来源与正式提炼均使用同一清洗逻辑。规则变更用于后续处理，不静默重写旧历史。
- `POST skills/cleaning/preview` 只做本地去噪；`POST extraction/preview` 比较已保存规则和草稿，最多两次模型调用，不写资料。界面说明发送样例到当前模型；默认不附带真实旧记忆。
- 口语需求保存为 `learning.normalization`：明确需求、用户逐字表达的验收要求、待确认问题。需求与简洁答案一致，原话通过 evidence 保留；缺少原话、推断、有疑问或虚构验收均不能自动入库。一次性需求为 `task_requirement`，不自动学习为永久习惯。
- 项目历史显示现有 AI 项目汇总及来源时间；它作为历史快照展示，不回灌为当前有效要求。任务断点页仅列任务。
- 无新数据库、新服务或前端依赖。旧数据、用户自定义规则与已有协作版本保留；验证使用合成数据与替代模型，真实旧记忆不送外部模型。
