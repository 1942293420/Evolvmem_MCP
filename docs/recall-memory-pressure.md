# 召回检查的内存与重复工作优化

本文按实施批次记录召回检查的优化与边界。本轮新增角色预检元数据复用、能力向量候选批读、经验初始检索输入复用，以及 LAN 后台物理检查执行预算；这些改动的生产效果须另行验证。

## 既有的原文保留、初始化与恢复调度优化

较早一批包含三项范围有限的修复：减少价值评估期间无用的原文保留，消除初次初始化内的重复检查，并延长连续失效的能力索引恢复轮次之间的等待。这些改动不迁移数据库，不改变项目分类和原文存储，也不降低召回的来源、资格与证据要求。

1. **价值评估缓存只保存证明哈希。** `capability_assessment._rows_read` 仍对每个来源执行当前读取，同一次调用内仍只读一次。此前缓存保留每份读取结果中的完整原文、角色与状态，后续实际只使用 `proof_hash`；现在仅保存哈希和独立的来源缺失标记，并立即释放临时完整结果。来源不存在与哈希值为空仍按原语义区分，损坏的证明结构仍报错。来源版本、原文证明、来源印记、单元证明、策略及历史评估检查不变。该改动不压缩或删除存放的原文，也不跨请求沿用缓存。

2. **首次初始化共享同一轮观察。** `ContextService.initialize` 保持依赖、数据库与索引的原初始化顺序，仍先执行 `_refresh_health()` 再返回 `status()`。这两步在本次调用内共享投影、向量与计数检查结果；首次物理完整性检查和文档结构核验仍执行，未初始化的向量仍不能使 PRIMARY 模式提前就绪。共享范围在成功或异常退出时恢复，后续独立状态查询不复用此次结果，其他模式与同参数再次初始化的行为保持不变。

3. **连续失效的能力索引恢复单独退避。** 当一轮恢复中任一资料空间返回 `status=partial` 且 `stale` 为正整数时，计入独立的连续失效次数。默认轮次结束后的等待依次为 **60、120、240、480、900 秒**，之后保持 900 秒；这不是单次恢复的执行超时。没有该类失效的一轮会重置此计数，普通未完成批次不因此延迟。原失败退避保留，同时存在时采用较长等待。每个资料空间的报告原样返回，`dirty`、`ready`、待处理数量和已处理结果不被改写；证明不完整的内容仍保持待更新。任务不会因此被删除，也不会把失效核验当作成功。

能力召回仍保留候选资格及最终选中来源的检查；经验召回仍沿用原资格、项目范围、适用条件与验证证据链，并在查询前后检查对应资料空间的后台准入。其他 Context 操作仍沿用原检查。以上三个补丁不扩大后台准入的适用范围。

验证包括该评估缓存不再让完整原文对象跨来源存活、原判定与读取次数一致、首次初始化真实重复扫描的反例、四种模式与异常清理、退避时序和多资料空间报告不变。该历史批次的集成验证记录：三个补丁合并后的 Linux 原生回归 **255 项通过，33.99 秒，测试进程峰值 266.9 MiB、swap 为 0**。这些数字描述测试运行，不代表生产召回延迟或生产服务内存上限；发布后的运行观察仍须单独记录。

这些修复针对已确认的额外保留与重复工作，**尚不能证明全部 OOM 原因已消除**。它没有完成 PostgreSQL 迁移，也没有完成十几人并发或读写延迟 SLO 验收。源码回归通过与生产效果验证分别记录，不以测试结果替代现场证据。


## LAN 完整性检查的统一管理

LAN 托管开始提供服务前，为每个资料空间显式设立一个物理检查所有者。常驻 Context 服务与后台健康状态读取同一份已提交数据的完整性记录，不再各自启动定时扫描。启动时原来的首次完整检查仍执行；交接不把未绑定新所有者与配置指纹的旧成功直接当成新基线。已在运行的旧扫描实际退出后才开始新扫描，旧扫描晚到的结果不能覆盖新状态。

记录绑定数据库路径、设备与文件标识、已提交结构版本、配置指纹及协议，并有单调递增版本。物理检查结束时立即发布；失败会撤销原成功并使请求健康缓存失效，无需等后面的语义检查。所有者关闭或确认边界变化后不自行恢复，也不退回前台重扫。物理成功不能清除语义检查错误、伪造完整就绪或刷新旧诊断。

事务仍执行自己的真实完整性检查，不能借用其他连接的已提交成功；同时遵守已确认的关闭、边界异常或物理失败。事务中的临时结构变化不发布成全局结构状态，回滚不会因此永久损坏共享证明。非 LAN 构造及独立 Web 保留原生命周期。

保留原最长五分钟有效期和提前刷新条件；缓存命中不会续期。这项改动消除重复所有者，但不保证耗时过长的下一轮一定赶在到期前完成，也不证明冷启动或所有内存压力已解决。扫描日志只记录开始、结束、耗时、匿名数据库标记和固定结果类型，不记录正文、SQL、路径或配置内容。原文、数据库迁移与向量内容均不因本项修改而变化。


## 独立经验查询与返回前复核

LAN 的经验召回使用请求独立的只读连接、快照、业务服务和缓存，不占用写入调度锁。它与能力查询共用两个重查询名额，所有退出路径释放连接和名额；共享模型引擎仍协调计算，不因请求结束而关闭。个人与公共空间分别读取、分别核验，不承诺跨库原子快照。独立 Web 和其他 Context 操作不因此切换读取方式。

保留原经验排序、项目范围、适用条件与验证规则；新增的词面候选也经过原来源资格检查。结果由初始快照选出，返回前核对配置、数据库身份、索引文件、后台准入、当前资格与时间窗口。期间发生 SQLite 提交时，只复查有界的命中正文、元数据和数据库证据依赖；相关变化或依赖超限会拒绝旧结果，无关提交且索引文件未变时可保留原结果。索引文件变化仍拒绝，未将它视为无关变更。新资料是否改变全局排名，要由下一次查询决定。

这项复核不把后台健康当作经验有效性证明，也不等同于能力召回对外部原文档案的来源核查。SQL 预算不限制模型和所有文件读取的总耗时；两个查询名额不代表已经完成十至二十人混合并发验收。生产延迟和内存仍须单独观察。

## 能力索引全量审计的正文驻留

常规资格路径先读取有序整数 ID，沿原批量资格规则计算，再逐行读取正文核对证明。保留原快照边界、计数、待处理集合及判断顺序；自定义资格回调继续使用原路径。此修改减少同时驻留的正文，不减少全量审计范围，不保证全量扫描耗时或所有内存问题已经解决。


## LAN 首次物理检查的严格交接

仅 LAN 显式启用首检凭据：真实首次检查前后分别读取数据库路径与文件身份、严格结构版本、结构定义摘要、配置对象及实际配置文件状态。两次完全一致且实际检查成功，才签发进程内凭据。首次检查仍执行，不把裸 ready 状态或旧诊断当作证明。独立 Web 和其他构造默认不启用此交接。

接管时再次核对当前完整边界、原始服务身份、检查代数、原缓存结果与真实完成时刻；已关闭、失败、存在尚未退出的旧检查、配置或结构变化均不接收。配置文件检查仅保护首检至接管这一过程，不增加配置热重载功能。采用凭据不更新检查完成时间，不伪造语义检查就绪，后续语义诊断继续独立执行。

保留最长 300 秒有效期及 60% 提前刷新规则。未到刷新时点的既有库正常重启可省去立即重复的物理扫描；已达到刷新时点、凭据过期、首次建库或真实升级仍可能扫描，不能承诺所有启动都只扫描一次。较慢物理扫描超过有效期的问题不由本项解决。

原版本计数触发器初始化每次无条件删除再创建，会让同一结构的 schema cookie 增加。现在逐项比较实际完整 SQL，相同定义不执行 DDL；缺失或不同仍按原方式重建，保留数据变化时原有的 revision 递增规则，不忽略真实结构版本差异。

HTTP 传输测试的合成夹具先等待真实后台工作完成三个空间的基线检查，再验证写入和幂等行为；项目事件引用测试在初始化前设置 primary 模式。原 ID 碰撞、返回内容与幂等断言保持，运行中配置变化仍拒绝旧证明。


## 单次来源读取的预算预检复用

能力原文与角色证明的内部调用链可能多次预检同一任务。现在仅在 OriginalRead 的同步读取范围中，并由现有 provenance_snapshot 确认同一连接、query_only、事务及数据/结构版本时，复用首次成功的任务预算元数据。每次命中仍核查 snapshot reader 与连接；每个 digest 的单元大小 SQL 仍执行。独立调用、调用方事务或缺少受检快照时继续原路径，不能仅凭 in_transaction 或布尔标记借用缓存。

只保留成功的范围、长度与身份元数据，不缓存原文、失败结果或最终资格决定。返回数据深拷贝；每个 OriginalRead 开始和结束清空，受检 reader 改变也清空。最多保留 8 个任务，并以无需编码超长文本的保守序列化上界限制累计 2 MiB；单条过大不缓存，累计超限淘汰后重新读取。这是元数据预算，不是整个进程 RSS 上限。

策略读取、实际正文/角色哈希及最终来源证明保持原流程。预检元数据本身只依赖当前数据库快照；OriginalRead 的入口和退出仍验证策略及连接状态。索引候选、事实排序与返回前的最终检查继续使用各自独立快照，不能跨阶段借用证明。本项不改变候选数、排序、结果或字符预算。

匿名 trace 新增 capability_role_preflight 与 capability_role_structure 两个固定计时名称；不记录任务 ID、查询或正文。structure 包含内部 preflight 时间，二者不能相加当作总耗时。原生回归与真实服务观察分别记录，不能仅由 SQL 次数下降宣称线上提速。


## 能力向量候选的有界批读

能力向量检索沿原排序分窗，每窗最多 20 个 ID。在实际受检的同一只读来源快照内，一次读取该窗的记忆，一次读取其完整来源行；来源逐行归并到原有的项目集合与来源计数，不额外积累完整来源行列表。进入下一窗前释放上一窗列表，已选结果与至多一个循环局部对象仍可能存活；这不是整个请求的内存上限。

批读保留原 ID 顺序、重复项的独立返回对象、缺失记录、JSON 解码、项目集合与来源计数语义。自定义资格回调和自定义文本解码器仍走原逐项路径，保留回调及解码顺序。来源中的坏文本、坏 JSON 或读取错误不会被跳过、修复或重试。项目字段本身不构成授权。

候选范围、窗口大小、排序、分数、分类过滤、资格与向量证明核查、够数即停及无效候选回填均保持原规则。返回前的来源与权限检查不借用上一阶段的证明。一个满窗的记忆／来源 SELECT 从逐项最多 40 次变为 2 次，只描述这两类读取；受检快照的元数据查询及其余证明检查仍执行，不能据此推算整次请求耗时。

## 经验初始检索输入的受限复用

仅 LAN 经验查询的初始只读快照启用输入复用，绑定实际资料空间、服务、连接、线程与读事务。复用的是原始检索记录、来源支撑行与资格判断所需的数据库行；每次仍调用原资格函数，不缓存资格结论、有效时间判断、来源家族赢家或向量可信结论。按 ID 懒读取来源，保留原短路及错误行为，不提前读取未访问的候选。

每个资料空间最多保留 1,024 个输入，并使用累计 8 MiB 的保守序列化权重预算。过大输入按原路径读取，不截断；返回对象独立复制。预算判断不先编码长文本或展开整个对象，但 SQLite 读取、对象转换及复制仍可能分配内存，因此不是进程 RSS 的硬上限。

范围只由受信的 LAN 读取所有者管理，不跨请求、空间或任意调用方替换的事务；它也不会自行开始、提交或回滚事务。初始检索结束后，先退出复用范围，再构建选中结果证明和执行全部最终复核。返回前仍使用原后台准入、配置与索引边界、当前资格、时间及选中依赖检查；没有把初始缓存当成最终证据。独立 Web、独立检索调用及写入路径保持原行为。

原向量窗口、候选预算、排序与返回 DTO 不变。合成夹具中重复 SELECT 的减少仅说明局部重复读取被消除；边界 PRAGMA、完整向量核验及最终证明仍有成本，尚不能据此认定线上延迟下降。

## LAN 后台物理检查的执行预算

只对 LAN 后台所有者执行的完整物理检查增加预算：从本次检查开始计算，取当前正有效期与 300 秒的较小值。它与证明有效期是两个约束，不改变原最长 300 秒有效期，也不为旧证明续期。首次同步初始化、默认独立调用、非 LAN 与独立 Web 路径保持原行为；本项不解决初始监听前的等待。

预算直接落实到执行 `PRAGMA quick_check` 的只读连接，采用 SQLite 进度回调、最多 100 毫秒且不超过剩余预算的锁等待，以及实际关闭连接后的最终时间核查。仍完整检查并验证原数据库身份与结构版本；部分检查、超过预算的成功或晚于关闭要求返回的结果均不能发布为有效证明。没有另开并发扫描，也没有用等待者超时冒充扫描已退出。

超时使用 `health_physical_timeout`；按 SQLite 数值错误码识别的 BUSY／LOCKED 使用 `health_physical_busy`，表示锁冲突导致检查未完成。这两种情况立即撤回旧成功及成功时间戳，推进所有者版本，使请求健康缓存失效；事务内查询也不能用本地检查绕过撤销。它们不直接表示数据库损坏。其他失败保留原 `health_physical_failed` 路径，这个通用代码本身也不是损坏的取证结论。关闭与完整数据库／配置边界变化仍有更强的拒绝优先级。

仅超时与锁冲突跳过本轮后续重语义检查；普通失败处理不扩大改变。实际扫描和连接退出后，由原后台调度继续处理其他资料空间，下一正常周期必须真正完成检查才可恢复。没有自动重试、采用旧首检凭据恢复、伪造就绪或续期。

这是防止异常长检查长期占用后台的限制措施，不保证持续就绪。取消为 SQLite 协作式机制，无法承诺立即打断内核 I/O；扫描未真正退出前，仍由原工作线程持有。原外层元数据事务未在本批拆分，其他检查的成本也仍存在。本项不改变来源资格和最终召回证据链，不代表全部内存压力、数据库迁移或十几人并发目标已解决。

## 本轮验证口径

本轮对应八个召回运行时文件与四个物理预算运行时文件，Linux 对应原生回归已通过。测试分别核对原 DTO、排序与读取边界不变，范围退出后的最终证明，真实 SQLite 取消／锁冲突分类、晚成功不续期、关闭优先与默认接口兼容。发布后的生产效果仍待验证；不能把局部 SQL 次数、合成计时或较早批次的测试数字视为本轮线上提速验收。本文不宣称这些改动已经在生产实现延迟或内存目标。
