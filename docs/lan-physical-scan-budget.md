# LAN 后台物理检查的执行预算

LAN 后台持有的 SQLite 完整物理检查使用独立执行预算：从本次检查开始计算，取当前正有效期与 300 秒的较小值。证明有效期仍为 300 秒上限；执行预算不会给旧证明续期。默认独立调用、非 LAN 路径和首次同步初始化保持原行为。

预算直接设置在执行 `PRAGMA quick_check` 的只读连接上，采用 SQLite 进度回调、最多 100 毫秒且不超过剩余预算的锁等待，以及实际关闭连接后的最终检查。仍执行完整检查，并核对原数据库路径、设备号、inode 和 schema cookie。超时返回的部分检查或晚到的成功不能发布为新证明。

执行超时使用 `health_physical_timeout`；根据 SQLite 数值错误码识别的 BUSY/LOCKED 使用 `health_physical_busy`，表示锁冲突导致检查未完成。它们都撤回旧成功、清除成功时间戳、推进所有者代数，并使请求健康缓存失效。事务内查询也不能绕过撤销。其它失败保留原有 `health_physical_failed` 路径；该通用代码本身不是数据库损坏的取证结论。

超时和锁冲突这一轮跳过后续重语义检查，实际扫描结束后由原调度继续处理其它库；下一个正常周期必须真正完成检查才可恢复。不会自动重试、并发扫描同一库、借旧初始化凭据恢复、伪造就绪，或把等待超时当成扫描已经退出。关闭与数据库／配置边界改变保持更强的拒绝优先级。

这是限制失控检查的措施，不保证持续就绪。SQLite 取消是协作式的，无法承诺立即打断内核 I/O；正在执行的扫描及连接仍由原工作线程持有至真实退出。此改动没有新增线程或进程，没有改变完整性证明、来源资格和最终召回证据校验，也没有完成数据库迁移或解决全部内存／初启问题。
