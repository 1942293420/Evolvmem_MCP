# EvolvMem 提炼质量与安全强化设计

日期：2026-08-03  
状态：已获用户逐段确认

## 背景与证据

EvolvMem 已将会话提炼提供商切换为可配置模式，默认使用 DeepSeek V4 Flash 非思考模式，并采用 `{"memories": [...]}` JSON Object 协议。真实 API 和完整测试均已验证基本调用链路。

对 149 条 Claude-mem 历史摘要进行真实 A/B 后，发现主要风险不在模型能力，而在提炼管线缺少确定性约束：

- Flash 能稳定返回合约 JSON，但会保留部署结果、测试数量、临时状态等短期信息。
- Pro 召回更多细节，却产生更多可从代码、日志和文档重新获得的噪声；在最多 8 条的限制下，前 8 条容易被单一项目占满。
- 两个模型都输出英文，因为提示词没有强制中文。
- 第一轮 Flash 复述了历史临时测试密码，证明只依赖模型判断和有限 Token 正则不安全。
- 当前持久化按模型顺序截取前 8 条，排在后面的 pinned 用户偏好可能被丢弃。
- 当前 MemoryStore 写操作逐条提交，批次中途失败可能产生部分落库。

## 目标

1. 继续使用 DeepSeek V4 Flash 非思考模式和单次提炼请求，不增加正常路径的模型调用次数。
2. 确保凭据不会以明文发送给模型、写入数据库或进入日志。
3. 强制提炼正文使用中文，同时保留代码标识符、产品名和稳定 key 的英文形式。
4. 丢弃明确的一次性状态，保留长期偏好、约束、决策、业务规则、架构原因和可复用故障根因。
5. 在数量限制前完成过滤、同 key 去重和质量排序，保证 pinned 与高重要性候选优先。
6. 将摘要和原子候选作为一个 SQLite 原子批次写入，避免半完成状态。
7. 保持现有完整会话优先、上下文超限降级、网络重试和离线补提炼语义。

## 非目标

- 不增加 Flash/Pro 自动路由。
- 不增加第二次 LLM 审核调用。
- 不建设持久化评测平台或模型排行榜。
- 不自动切换到 Kimi；Kimi 仅保留为手动配置的备用提供商。
- 不修改原始 `wire.jsonl`、历史记忆正文或已归档记录。

## 选定方案

采用“双层确定性门控 + 单次 Flash”：模型负责语义理解和候选生成，代码负责凭据安全、最终取舍、排序和原子落库。

提示词强化或更换更强模型只能改善概率，不能提供安全保证；第二次模型审核会增加延迟和成本，仍不能替代确定性安全门控。

## 架构与职责

### `evolvmem/auto_extractor.py`

- 使用中文编写提炼指令。
- 明确要求 `value` 与说明性 tags 使用中文；代码标识符和产品名可保留英文。
- 保持顶层 `{"memories": [...]}` 协议，并继续兼容旧顶层数组响应。
- 强调长期保留规则和一次性信息排除规则。

### `evolvmem/extraction_policy.py`

新增纯策略模块，隔离安全和质量判断。公开职责为：

- `redact_messages(messages)`：返回脱敏副本和脱敏计数，不修改输入对象。
- `sanitize_summary(value)`：替换摘要中的敏感片段；无法形成安全、有效中文摘要时返回失败。
- `evaluate_candidate(candidate)`：返回接纳或拒绝，以及稳定的原因代码。
- `rank_candidates(candidates, limit=8)`：同 key 去重、排序并截取候选。

策略函数不得读取数据库、调用网络或打印候选正文，保证可独立测试。

### `evolvmem/kimi_hooks.py`

- 保持 Kimi Code SessionStart/SessionEnd 生命周期适配器角色。
- 按“读取消息 → 脱敏 → 构建提示词 → 调用模型 → 解析 → 策略过滤 → 排序 → 原子持久化”编排。
- 继续复用当前提供商配置、超时预算、HTTP 重试和上下文超限降级。

### `evolvmem/memory_store.py`

- 提供外层事务上下文，使 add/replace 在批次事务内不自行提交。
- `replace` 在外层事务中不重复执行 `BEGIN IMMEDIATE`，避免嵌套事务错误。
- 批次全部成功时提交，任一 SQLite 写入失败时整体回滚。

## 数据流

```text
wire.jsonl
  → 提取完整 user/assistant 消息
  → redact_messages（只产生脱敏副本）
  → DeepSeek V4 Flash 单次请求
  → JSON 解析与 SESSION_SUMMARY 合约检查
  → sanitize_summary
  → evaluate_candidate（逐条安全/质量/语言判断）
  → rank_candidates（同 key 去重、排序、最多 8 条）
  → SQLite 原子批次：摘要 + 原子候选
  → 提交后同步向量索引
  → ExtractionResult
```

正常 SessionEnd 和 stale-session worker 都读取 wire，不涉及记忆状态。手工进行历史重提炼验收时只允许读取 active 记录；archived 与 superseded 不进入模型输入，也不会新增生产重提炼入口。

## 安全策略

### 发送前脱敏

识别并替换以下内容：

- Bearer Token、常见 API Key、access/refresh token、JWT。
- `password`、`passwd`、`pwd`、`密码` 通过 `=`、`:`、`set to`、`是`、`为` 等形式赋值的值。
- PEM 私钥块。
- URL 中内嵌的用户名和密码。
- “密码/密钥存放在某文件或位置”的凭据定位信息。

替换标记只表达类别，例如 `[已脱敏:password]`，不包含原值。原始消息对象和 wire 文件保持不变。

### 返回后门控

- 普通候选包含凭据、临时/测试密码或凭据位置时整条拒绝。
- SESSION_SUMMARY 包含可局部识别的敏感片段时进行替换；替换后为空、低信息或非中文则整批返回 retry。
- 日志只记录候选 key、原因代码和统计，不记录 value 或匹配片段。

## 质量与语言策略

### 直接拒绝

- 临时或测试密码。
- 等待用户输入、稍后确认、暂时设置、一次性测试等临时状态。
- 仅描述某次测试通过、某次部署完成或某个提交号的记录。
- 已完成且没有长期决策、约束或原因的一次性待办。
- 不含中文说明的原子候选。

### 必须保留的类别

- 长期用户偏好和用户画像。
- 硬约束、安全开关和业务规则。
- 架构或技术决策及其原因。
- 已废弃方案及替代原因。
- 可复用的故障根因和防复发规则。

“Broker 完成前禁止写操作”属于持续有效的安全约束，不能因含有“前/直到”一类时间词而误删。短期判断必须基于明确组合规则，不能仅依赖单个关键词。

### 中文合约

- SESSION_SUMMARY 必须包含中文，否则本轮不写入并返回 retry。
- 单个原子候选 value 不含中文时只拒绝该候选。
- key、代码标识符、产品名和必要缩写不受中文限制。

## 去重、排序与数量限制

先过滤，再进行同 key 去重。相同 key 保留排序元组更高的候选：

```text
(是否 pinned, importance, confidence, 模型原顺序)
```

全局排序使用相同规则：

1. pinned 优先；
2. importance 降序；
3. confidence 降序；
4. 分数相同时保持模型原顺序。

排序完成后截取最多 8 条原子候选。SESSION_SUMMARY 单独处理和持久化，不参与去重、不占 8 条配额。

## 错误处理

- 脱敏失败：不调用模型、不写数据库，返回 retry。
- HTTP 408/429/瞬时 5xx 和网络超时：沿用当前退避和 240 秒共享预算。
- JSON 错误、缺少摘要、摘要无法安全脱敏或摘要非中文：不写数据库，返回 retry。
- 单个普通候选被策略拒绝：记录原因计数，继续处理其他候选。
- 所有原子候选被拒绝：只要摘要安全有效，仍可 completed。
- SQLite 任意一步失败：回滚摘要和全部原子候选，返回 retry，离线 mtime 不推进。
- SQLite 成功而向量同步失败：保留数据库提交，记录无正文的告警；启动时一致性检查负责修复向量索引。

## 可观测性

每次提炼输出单行统计，不包含候选正文：

```text
provider=deepseek redacted=2 accepted=6 rejected_sensitive=1 rejected_ephemeral=4 rejected_language=2 persisted=7
```

`ExtractionResult` 保持 completed/skipped/retry 主状态，并携带 persisted、reason、rate_limited；策略统计可作为结构化字段或内部统计对象传给日志，但不改变 stale-session worker 的终态判断。

## 测试设计

### 安全过滤

- 使用合成值覆盖 Token、JWT、密码赋值、私钥、URL 凭据和凭据位置。
- 验证脱敏副本与原始消息相互独立。
- 验证敏感候选不能落库，日志不含原值。
- 验证“密码策略要求 12 位”等不含凭据值的普通描述不会被误删。

### 质量、语言与排序

- 提示词明确要求中文和长期信息。
- 临时密码、等待输入、纯测试结果和纯提交记录被拒绝。
- 持续安全约束被保留。
- 同 key 候选保留质量更高者。
- 排在模型末尾的 pinned 候选仍进入前 8 条。
- importance、confidence 和稳定顺序符合定义。
- 摘要不占原子配额。

### 事务和状态

- 在第三条写入处注入异常，验证摘要和前两条全部回滚。
- 验证 SQLite 提交后向量失败不会删除数据库记录。
- retry 不推进 stale-session mtime；completed/skipped 才推进。
- 保留现有完整会话优先、HTTP 400/422 上下文降级、429/超时回归测试。

### 真实 Flash 验收

使用本机 Claude-mem active 历史做一次只读、不落库验收：

- 外发前疑似凭据全部脱敏。
- 摘要和所有接纳 value 均包含中文。
- 接纳结果中敏感候选为 0。
- archived ONBOARDING、临时密码、单次测试数和纯提交记录不出现。
- 最终前 8 条覆盖 pinned 用户偏好、核心决策和关键约束，而不是被同一项目的过程细节占满。

自动测试在 HTTP 边界使用结构完整的模拟响应，不断言真实模型必须输出固定句子。真实模型只用于最终人工验收，避免随机性导致测试不稳定。

## 兼容性与取舍

- DeepSeek V4 Flash 继续作为默认模型；V4 Pro 和 Kimi 可人工配置，但共享相同策略门控。
- 旧顶层 JSON 数组继续解析，避免历史或备用提供商响应失效。
- 确定性规则可能漏掉未覆盖的新凭据格式，因此发送前和返回后必须共用同一敏感模式库，并保留扩展测试入口。
- 质量门控选择保守拒绝明确短期信息，不尝试用复杂启发式完全替代模型语义理解。

## 成功标准

1. 完整自动化测试、Python 编译和差异检查通过。
2. 合成安全测试中明文凭据发送、落库和日志泄漏均为 0。
3. 批次写入失败时 SQLite 不存在部分新增或替换结果。
4. 真实 Flash 验收满足中文、安全、active-only 和前 8 条覆盖标准。
5. 正常路径仍为单次 Flash 请求；未增加模型审核或自动路由。
