# 完整任务整理链路

## 已确认目标

- 原始会话保留；按需求提出、处理过程、结果组织任务。
- 同一需求中的更新失败、连接提示等修复放在同一个任务内。
- 先 AI 整理任务来龙去脉，再判断项目，最后提炼需求、办法、结果、依据。
- 未完成、失败、尚未验证均如实记录；摘要不成为成功证据。
- 审核一条完整任务；同一窗口阅读会话并定位来源，长原文按需显示。

## 实施边界

- 复用 SQLite、现有后台工作线程、现有模型配置；不增加服务或模型依赖。
- 原始档案不改写；以会话来源清单连接增量档案，业务任务可跨采集批次。
- 任务识别每窗保存进度，完成的整理稿复用；漏段、虚假引用、错误结构停止并明确提示。
- 任务识别与经过整理都由模型选择原文证据编号，程序按编号取原话与角色；旧逐字引用兼容但须核验。明确没有处理步骤或待办的 null 归一为空列表，不编造内容。
- 现有后台线程同时接收新增资料；旧资料错误不会阻塞后续来源。Windows 会话的完整快照被新版本替代后，旧会话任务自动退出并关联当前版本，避免反复重试旧原文。
- 分批读取只限制模型输入量；任务标识贯穿各批，可在插入别的任务后继续。
- 整理稿独立保存需求、原因、各次处理、结果、未完成事项及逐字来源引用。
- 保留原人工归入、排除、个人通用和多项目规则；范围变化先重新核对。
- 所有提交、重试、按新规则整理与新增到达默认走完整任务流程；旧待审/失败资料后台分批接续，已结案资料保持原状。
- 兼容旧数据的读取与人工决定；公开提交接口统一创建会话任务，无需点击转换。

## 工作包与验收

1. 会话来源与任务识别
   - 新增会话来源清单，严格核对原生会话身份、可见性、去重和版本。
   - 新增任务分段器：跨读取窗口沿用任务编号，引用真实位置，覆盖全部原文。
   - 测试：跨档案同任务、穿插后继续、新需求另起、来源缺失/变化和重复入队。
2. 整理、分类、提炼
   - 新增任务整理模型步骤；程序校验逐字依据，不把摘要当原文。
   - 完整任务写入后分类，再通过原提炼持久化链路保存有来源的经验结构。
   - 测试：调用顺序、旧人工决定保留、冲突与范围变化、经验追溯和失败重试。
3. 审核页面
   - 左侧完整任务，右侧需求/原因/处理过程/结果及项目选择；旧碎片显示自动整理状态，后台完成后当前阅读内容自动更新。
   - 原文在同一窗口读取；逐条排除、批量预览、个人通用、多选项目和草稿继续可用。
   - 测试：实际浏览器操作、分页定位、切页保留状态及手机/平板/桌面布局。
4. 整体验收与上线
   - 当前规则加模拟长会话执行真实模型验收；获明确授权的旧会话使用当前模型在独立诊断库复现。
   - 相关 Python/浏览器回归、人工记录前后校验、工作原理图及架构说明同步。
   - 验证后部署原 Web/MCP 服务，回读总控台登记，提交并推送公开源码。

## 验证范围

- 默认提交、新旧资料接续、失败恢复、原文完整覆盖、人工决定及逐条排除。
- 完整任务的需求、过程、结果审核；同一会话批量判断、个人通用和多项目保存。
- 长原文分页、后台更新、跨页草稿、刷新复用已有结果、三种屏宽布局。
- 原有项目历史、来源追溯、纠正传播、向量同步事务与旧数据兼容。
- 真实旧会话仅在获授权的本地独立诊断库验证；源码导出不包含正文、模型回复或数据库。

## 稳定知识身份与人工归档（2026-10-18）

- AI 只建议项目；用户选项目直接保存，或暂不归档。人工决定绑定原文范围及稳定知识 ID。
- 同源重复整理、改摘要、拆分再合并沿用原决定与历史记录；暂不归档也不会因重组重新催审。
- 明确项目下原文完全一致的已确认事实可增加来源，不重复归档；仅文字相似、无明确项目或新增要求仍等待用户决定。
- 整条知识改归属时，已识别的重复来源同步；仅改一部分则拆开决定，其他内容保留原归属。
- 旧人工记录按当前来源或完全一致的内容逐步接入，保留原历史 ID；不触发整库模型重跑。
- 知识身份、来源映射、决定与归属保存共用事务；旧摘要兼容与来源有效性同步校验。
- 验证：208 项相关 Python 检查通过；直接归档、切换资料、产品模块三套真实浏览器脚本通过，包含四种屏宽的工作原理图。扩大检查发现 17 项既有基线失败（旧归档/队列契约），不计入本次通过数，也未通过放宽生产规则使其通过。
- 第一批只交付稳定身份与人工决定；事实与关系的后续实现见下一节，统一知识目录和 Agent 召回已在第三批接入，见下文。


## 事实版本、知识关系与分歧（2026-10-18）

- 入口：自动整理 → 事实与分歧。查询对象、已归入项目、适用条件或业务日期；内容确认与项目归档分开，AI 始终不能指定正式归属。
- 完整任务的同一次模型整理增加 `facts`、`relations`；每个结论逐字核对原文。缺失或不合法的补充信息不阻塞原有直接归档。来源、原始条件、收录时间保留；模型推测的结束日期不会使旧事实失效。
- `knowledge_facts.py` 在现有 SQLite 中维护版本、来源、类型化关系和人工内容决定。相同对象名称与属性只作可拆的阅读聚合；无明确项目名称的对象限定在原知识内，暂不做任意同义实体合并。
- 不同环境分别查看和确认；同一条件的互斥说法聚成一项分歧；有明确日期的变化显示新版本待核对。已确认的新版本不会被晚导入的旧资料替代，按业务日期仍可查看旧结论。
- 分歧可采用结论、补充各自适用情况或暂缓；重复原话只补来源，不重开已处理分歧。补充条件若与第三条事实冲突，会显示新分歧。拆开错误聚合保留双方原文和人工项目决定。
- `ownership_reasoning` 的修改对象和验证场景分别形成建议关系；“属于项目”只由人工归档记录生成。关系本身也是带原话的事实，只有关系而无其他属性时仍可查询。
- 验证次数只读取现有经验服务已绑定原始证据的事件，并核对原话、条件，按原始事件去重；助手陈述、重复转述、归档和确认事实都不增加验证次数。
- Web/CLI 共用 `GET facts`；查询参数 `q`、`project`、`at`（日期）、`conditions`（条件字典）。人工操作用 `POST facts/confirm`、`facts/resolve`、`facts/split`，携带页面读取的 `expected_revision`，事务失败整体回滚。
- 页面缓存已读结果与未保存条件草稿，切换标签不重新读取；保存或主动刷新才更新。原话显示来源客户端和时间；业务时间与收录时间分别展示。
- 验证：22项新场景、相关253项 Python 测试通过；`knowledge_facts.e2e.cjs` 验证保存失败重试、采用、补条件、暂缓、拆开、缓存及390/768/1440宽度；`product_modules.e2e.cjs` 验证原有业务模块、七类图与四种屏宽。
- 真实配置模型仅接收模拟资料，在独立库走通整理到查询：一次通过样本为4组5个事实版本，修改/验证关系可查，保留新旧业务日期，未经人工的项目归属与虚增验证均为0。此前输出曾推测旧版本截止日期、遗漏部分关系；现有保守校验及关系独立保存覆盖这些情况，不据此承诺任意文本的提取质量。
- 本批只接入后续资料及正常任务整理，不执行正式历史整库模型重跑。统一项目知识目录及默认 Agent 召回现已接入；事实管理接口仍可独立使用。原有17项旧契约测试失败不计入本批通过数。


## 项目知识目录与统一召回（2026-10-19）

- 入口：项目知识 → 选择项目。默认打开知识目录；按业务规则、运行与部署、问题处理、决策变化、开发经验及参考知识导航，空目录不显示。历史摘要、历史记录、经验问答与来源纠正入口保留。
- `project_knowledge.directory` 从现有 Context Core、人工归档与事实记录生成只读视图，不新建权威数据副本。当前有效来源、归属、撤回及适用状态共同决定可见内容；关系不会传播项目归属。
- 详情展示当前说法、适用条件、原文、其他版本、关系建议、独立验证次数。相同条件的未解决分歧同时显示双方；未归档的另一方单独标识，不成为项目结论。采用结论而未归档其资料时继续提示这个差别。
- 旧资料或模型没有提炼事实时，直接读取已归档原文摘要与来源，不要求重新分类。没有明确适用条件的旧资料不冒充匹配指定条件的事实；不重跑正式历史，不自动确认知识或验证成功。
- 页面 `GET /api/knowledge/directory` 与 `knowledge_recall(kind="knowledge")` 使用同一视图，支持项目别名、问题、业务日期 `at` 和条件字典 `conditions`。`auto` 包含项目知识；`both` 同时查询目录、历史与问答；显式 `history`、`experience` 保持原有含义。
- 召回保留已有语义检索与重排；按相关度与字符预算返回完整知识块，不能截掉分歧警告后留下单方结论。结构化结果包含版本与来源。`context_search` 和项目背景读取同步附带事实状态，避免旧摘要遮住已知分歧；跨 Agent 续接路由保持原状。
- 已打开的目录、原文、选中知识、查询条件与未提交查询草稿留在浏览器中。切页不重读目录；保存或刷新更新数据。迟到响应不能覆盖新查询，读取失败保留已有内容并可重试。
- 归档仍可在 AI 无结果时直接保存；回执显示实际归入项目的知识条数。知识详情中的“处理事实与分歧”可直达原有管理页。
- 验证：13项新增场景，相关397项 Python 检查通过；目录、直接归档、快速选择、产品模块四套真实浏览器验收通过，检查390/768/1440宽度及原工作原理图。正式库仅作只读检查：EvolvMem 项目268条资料可组成目录；批量读取同范围实测约0.05秒（环境与数据量变化会影响耗时）。
- 详细事实版本随第二批的新资料整理逐步补充；旧资料目前按已归档内容阅读，不声称全部历史已完成细粒度提炼。第四批实际对照与后续补齐结果见下节。
